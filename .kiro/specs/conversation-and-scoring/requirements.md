# Requirements — conversation-and-scoring

## Overview

When an unknown caller is in the screening flow, Ghostline must drive a
multi-turn spoken conversation, score each turn for scam signals, and decide
what to do next. This spec covers the conversation engine (`lib/conversation.ts`,
`lib/scoring/`), the Gemini integration, and the rules-layer scorer.

The turn route handler in `app/api/voice/turn/route.ts` calls `runTurn()` from
`lib/conversation-engine.ts`. That stub must be replaced with the real engine
exposed by `lib/conversation.ts`.

---

## R1 — Opening line

The first time an unknown caller hears Ghostline, the system must speak
exactly:

> "You've reached the {family_name} residence. This call is screened by
> Ghostline. Please say your name and why you're calling."

This line is emitted by `greetingTwiml()` in `lib/twiml.ts`. The conversation
engine must not repeat this line on subsequent turns.

---

## R2 — Persona constraints

Every reply generated by the conversation engine must follow the voice-persona
rules:

- Maximum 2 sentences per turn, under 25 words total.
- Patient and warm in tone; never sarcastic.
- Never accuse the caller of being a scammer. Use "I'm not able to connect
  this call." to decline.
- Never reveal, hint at, or repeat the safe word.
- Never confirm whether a safe-word attempt was close.
- Never give out personal information about the household (address, senior's
  name, family members' names, phone numbers).

---

## R3 — Rules-layer scoring

`lib/scoring/rules.ts` must implement a deterministic, synchronous,
zero-network scorer that evaluates caller utterances against the flag table
from scam-rules.md:

| Flag id | Points |
|---|---|
| `payment_method` | 40 |
| `secrecy` | 30 |
| `authority` | 30 |
| `emergency_story` | 25 |
| `urgency` | 20 |
| `remote_access` | 30 |

Each flag fires at most once per call regardless of repetition. The score is
the sum of unique triggered flags. The function must accept all caller
utterances collected so far (not just the latest turn).

---

## R4 — AI-layer scoring

`lib/scoring/ai.ts` must call `gemini-2.5-flash` via `@google/genai` with
`responseMimeType = "application/json"` and return a Zod-validated struct
containing:

- `reply` — the next persona line to speak.
- `risk_score` — integer 0–100.
- `flags` — array of flag IDs from scam-rules.md.
- `claimed_identity` — what the caller said their name or organisation is, or
  `null`.
- `claims_family` — `true` if the caller claims to be a family member.
- `requested_amount` — verbatim dollar/value mention, or `null`.
- `payment_method` — payment type mentioned, or `null`.
- `summary` — one-sentence running summary.

The call must have a 6-second timeout via `AbortSignal.timeout(6000)`. On
timeout, network error, or Zod validation failure the function must throw
`GeminiUnavailableError`.

---

## R5 — Score combination

`lib/scoring/combine.ts` must merge both layers into a single score using
the rules from scam-rules.md:

1. `combined = max(rules_score, ai_score)` — the AI may raise, never lower.
2. If `callback_denied` is `true`: `combined += 100` (applied first, so safe
   word can never cancel it).
3. If `safeWordCorrect` is `true` AND `callback_denied` is `false`:
   `combined = max(0, combined − 40)`.
4. The score for a call is monotonically non-decreasing: `combined =
   max(combined, priorScore)`.
5. Cap at 100 for DB storage.

Risk bands:

| Band | Range |
|---|---|
| LOW | 0 – 39 |
| MEDIUM | 40 – 69 |
| HIGH | 70+ |

---

## R6 — Gemini fallback

When `GeminiUnavailableError` is thrown, the conversation engine must:

1. Continue the call using rules-only scoring.
2. Use a scripted safe reply appropriate for the current risk band.
3. Log the fallback with `console.error` (not silently swallow it).
4. Not re-throw the error; the call must not drop.

---

## R7 — State transitions

The engine must map combined risk level to the next call state:

| Risk level | `claims_family` | `time_waster_enabled` | Next state |
|---|---|---|---|
| `high` | any | `true` | `time_wasted` |
| `high` | any | `false` | `scam_blocked` |
| `medium` | any | any | `screening` (keep screening) |
| `low` | `true` | any | `screening` (safe-word challenge) |
| `low` | `false` | any | `verified` |

Terminal states (`scam_blocked`, `completed`, `verified`, `transferring`) must
not transition further.

---

## R8 — Event persistence

The engine must persist:

- A `red_flag` event in `call_events` for each newly detected flag (flags
  already recorded for this call must not be duplicated).
- The `claims.risk_score`, `risk_level`, `claimed_identity`, and `summary`
  fields must be updated on the `calls` row after each turn.

---

## R9 — Conversation state from DB

All conversation history must be loaded from `call_events` rows of type
`transcript`. No turn data may be stored in module-level variables or
function closures. This is required because Vercel serverless functions do
not share memory between invocations.

---

## R10 — 10-second budget

The engine's Gemini call is capped at 6 seconds. Combined with DB round-trips
(≤ 1 s), the entire `runTurn()` call must complete well within Twilio's
10-second webhook timeout. The system prompt must be kept short enough that
Gemini responds within 6 seconds on a cold invocation.
